# 2A 部署與安全驗收

本文件供計畫維護人員使用。程式已準備好；本工作區未連線您的 Google 帳號，尚未建立真實試算表、部署 Apps Script、驗證個人 Gmail OAuth 或部署 Netlify。正式寫入預設關閉。以下實際帳號檢查須在您自己的 Google 環境完成；不要將密碼、授權碼、Token、內部試算表內容或帳號清單貼到聊天／GitHub。

## 1. 先確認授權範圍

`apps-script/appsscript.json` 明確要求下列三項，沒有郵件、外部請求或完整 Drive 讀寫範圍：

| OAuth scope | 使用原因及範圍 |
| --- | --- |
| `userinfo.email` | 從 Google Session 辨識存取者，不能從瀏覽器傳入帳號替代 |
| `spreadsheets` | 初始化及讀寫 Google Sheets；Google 此 scope 本身可涵蓋該帳號可存取的其他試算表，程式固定只使用私人設定中的一份 |
| `drive.metadata.readonly` | 透過 Advanced Drive v3 讀取檔案的 `capabilities.canEdit`，確認目前訪客有編輯權；Google 授權可能顯示可檢視 Drive 檔案中繼資料，這不是僅限單一檔案的 scope |

這是獨立 Apps Script 且以存取者執行，不能以 `spreadsheets.currentonly` 取代上述試算表 scope。此階段不以程式上傳 Drive 文件；匯出檔案下載後由人員放入受限 Drive 資料夾，不需要完整 Drive 寫入 scope。若組織不同意上述權限範圍，保持寫入關閉，採下方人工替代流程。

## 2. 建立測試環境及初始化

1. 在 Google Drive 建立僅供測試的空白試算表，分享設定維持「受限」。使用預定的受信任維護帳號擔任擁有者。不要使用真實服務資料。
2. 在 [Apps Script](https://script.google.com/) 建立**獨立專案**，僅由維護人員持有編輯權；一般管理員無需專案編輯權。將 `Schema.gs`、`Server.gs`、`Setup.gs`、`Index.html` 複製成同名檔案。
3. 專案設定勾選「在編輯器中顯示 appsscript.json 資訊清單」，以 Repository 的 `appsscript.json` 取代；服務面板確認已啟用 **Drive API v3**。若使用標準 Google Cloud 專案，亦需在該專案啟用 Google Drive API。
4. 專案設定 → 指令碼屬性新增 `SPREADSHEET_ID`，值為試算表網址 `/d/` 與 `/edit` 中間的字串。此值只存 Google 後端，不放 `.env`、前端或 GitHub。新增 `WRITE_ENABLED=false`。可選填 `TARGET_ORGANIZATIONS`、`TARGET_COURSES`（非負整數），首頁將目標與實際資料分列。
5. 用**試算表擁有者本人帳號**在編輯器執行 `initialize_`，閱讀並確認 Google 顯示的授權範圍。若函式選單顯示「沒有函式」，依下方「編輯器未列出私人函式」暫時改名後執行。它會建立六張固定工作表、初始管理員、草稿招募設定及初始化紀錄，保護 AdminUsers，保留原有資料。不要在表格手動輸入正式內容。
6. 再執行一次初始化，確認沒有重複管理員與招募ID。每次初始化都會關閉寫入並清除舊的安全驗收紀錄；維護時亦須重新驗收後才開啟。程式不會清空或遷移既有欄位；欄位不符會拒絕。預設 Sheet1 可自行刪除（僅在它是空白且無用途時）。
7. 建立受限的 Drive「2A內部備份」與「2A公開資料交接」資料夾，僅分享相關維護人員。兩者皆不要設為「知道連結的所有人」。檔案／文件上傳介面不在本階段範圍內。

可選使用 clasp 管理同一專案，但不強制安裝、不需要付費服務。`.clasp.json`、OAuth 本機認證檔已列入忽略，請勿提交任何憑證。初版建議由編輯器貼上檔案，較適合非工程同仁。

### 編輯器未列出私人函式

`Setup.gs` 的維護函式以 `_` 結尾，避免成為 `google.script.run` 可呼叫的入口；部分編輯器情況下，執行選單亦不會列出它們。初始化專案尚未部署時，可只將第 2 行的 `function initialize_() {` 暫改為 `function initializeDatabase() {`，其餘程式不變。儲存、等待完成，必要時重新整理編輯器，即可選取 `initializeDatabase` 執行。函式內原有身分、試算表編輯權限及擁有者檢查都會保留。

初始化完成後，立即將該行改回 `function initialize_() {` 並儲存，再進行任何測試或正式網頁部署。暫時改名的版本不可建立或更新網頁部署，也不可提交成正式原始碼。執行其他私人維護函式時，如遇同樣情況，可在編輯器暫去掉函式名稱最後的 `_`，完成後立即恢復；已有部署仍保留先前版本，直到私人名稱恢復後才可發布新版本。

若改名、儲存及重新整理後仍顯示「沒有函式」，請檢查專案中所有 `.gs` 檔案是否有貼入不完整、Markdown 的反引號或語法錯誤提示；不要刪除授權檢查來排除問題。

## 3. 增加第二位測試管理員

1. 在試算表分享中，將另一位受信任管理員加入為「編輯者」。不要公開分享試算表，也不要讓一般管理員再轉分享；擁有者可在分享設定停用編輯者變更權限及分享。
2. 擁有者在 Apps Script 的指令碼屬性暫時填入 `NEW_ADMIN_EMAIL`（只在 Google 私人介面填寫）。
3. 擁有者在編輯器執行 `addAdmin_`。程式建立 UUID、時間及操作紀錄，完成後移除暫存屬性。一般管理員不得修改受保護的 AdminUsers。停用方式見操作維護文件。

## 4. 部署測試網址

1. Apps Script「部署 → 新增部署 → 網頁應用程式」。
2. **執行身分：存取網頁應用程式的使用者**（USER_ACCESSING）。不得選「我」。
3. **誰可以存取：任何已登入 Google 帳號的使用者**，對應 manifest `ANYONE`。Google 中文 UI 可能只顯示「任何人」，請核對它要求登入 Google 帳號，並且不是 `ANYONE_ANONYMOUS`。不可選「任何人（包含匿名使用者）」。若當前帳號沒有對應的存取者執行及已登入使用者選項，停止部署並使用替代方案。
4. 使用實際 `/exec` 部署網址測試，不以 `/dev` 或編輯器執行結果替代。不同管理員使用不同 Chrome 個人檔案／無痕視窗，避免多帳號登入誤判。
5. 每位管理員各自完成 Google 授權。初始頁應顯示本人帳號及「唯讀模式」。Google 是否能在您的消費者 Gmail、OAuth 專案及部署組合可靠提供 email，必須實測；程式遇到空白、不同有效執行者或無法查核編輯權限會拒絕。

Google 可能要求外部 OAuth 同意畫面、測試使用者清單、應用程式驗證，或顯示尚未驗證提示。由專案擁有者依 Google 當時規定確認是否適用個人使用／有限使用者例外；若不適用，不得假稱可免驗證上線。處於外部「測試」發布狀態時，這些 scope 的使用者授權可能在七天後需重新授權。不要為繞過驗證而改成擁有者執行或匿名服務。

## 5. 寫入前的實際安全驗收

將真實測試紀錄留在受限 Drive，不存 GitHub。此處清單初始全為待測，不能因本機測試通過直接打勾。

| 測試 | 通過條件 | 實際結果 |
| --- | --- | --- |
| 部署設定 | /exec 使用 USER_ACCESSING 及 ANYONE；登入才可存取 | 待測 |
| 授權管理員 A、B | 各自授權後首頁顯示本人 email，各自可讀取測試資料 | 待測 |
| 未列白名單且無 Sheet 權限 | 無法進入；RPC 讀寫及匯出都拒絕 | 待測 |
| 具 Sheet 編輯權但不在白名單 | RPC 拒絕；不能修改受保護的 AdminUsers 加入自己 | 待測 |
| 白名單內但僅有檢視權限 | 首頁、內部列表、修改及匯出均拒絕 | 待測 |
| 取消／撤銷 Sheet 分享或白名單 | 下一次 RPC 即拒絕，不沿用前端登入狀態 | 待測 |
| 登出／未授權 Google 帳號 | Google 要求登入／授權；沒有匿名寫入能力 | 待測 |
| Session email 空白或執行者不符 | 拒絕操作；本機已有分支測試，實際遇到時不得改用前端email | 待測／無法人工觸發時記錄本機分支證據 |
| 公開預覽檢查 | JSON 只有公開欄位，不含內部備註、管理員、稽核；自由文字人工檢閱 | 待測 |

測試 RPC 可在 Apps Script 頁面的 HTML iframe 開發者工具主控台執行，例如：

```js
google.script.run.withSuccessHandler(console.log).listRecords('Organizations');
google.script.run.withSuccessHandler(console.log).saveRecord('Organizations', {});
google.script.run.withSuccessHandler(console.log).previewPublic();
```

未授權者預期收到 `ok:false`；不可有內部記錄。用同一矩陣檢查 `getBootstrap/getRecord/archiveRecord/deleteRecord/exportPublic`。所有變更測試只在隔離的測試試算表進行，不以測試帳號操作正式內容。不在白名單的人即使載入過頁面或知道 RPC 名稱也必須被伺服器拒絕。

完成上述**真實測試**後，由維護人在測試專案私下設定 `SECURITY_REVIEW_JSON`，再設 `WRITE_ENABLED=true`。下例是**未通過範本，會保持停用**；僅在各項有真實證據後，填入實際日期、正確設定、通過的數量及 true 值。後端檢查這份人工驗收紀錄；它不是向 Google 自動查詢目前部署設定，維護者必須負責核對。

```json
{
  "testedAt": "填入實際ISO日期",
  "executeAs": "尚待核對",
  "access": "尚待核對",
  "authorizedAccountsTested": 0,
  "unauthorizedDenied": false,
  "viewerDenied": false,
  "exportChecked": false
}
```

程式要求 executeAs=USER_ACCESSING、access=ANYONE、至少兩位授權帳號、有效測試時間及其餘三項 true，並且 WRITE_ENABLED=true 才允許內容變更及可下載匯出。每次操作仍重新檢查登入與試算表權限。

開啟測試寫入後，驗證新增／編輯不重複ID、兩個視窗編輯有版本衝突提示、下架與刪除確認、操作紀錄、公開快照無草稿、機構與課程關聯，以及公開網站預覽。驗收完成再建立獨立正式試算表與正式專案，重做初始化、分享及實際部署檢查，通過前仍維持關閉。

## 6. 公開網站與 Netlify

1. 本機如需覆寫設定，可複製 `.env.example` 為 `.env.local`。`VITE_CONTENT_MODE=published`；前台已在 `src/config/site.ts` 預設使用本專案提供的公開 Apps Script `/exec` 網址，可透過 `VITE_ADMIN_URL` 覆寫。空值覆寫會停用入口，不能保留舊的空白環境變數。後台網址是公開入口，可放 Vite 環境變數；email、Sheet ID、認證資訊不可放。入口連結不代表已通過多帳號安全驗收，驗收完成前仍保持唯讀。
2. 管理員下載公開 JSON，在私人 Drive 交接。維護人員下載到本機後執行：

```sh
npm ci
npm run content:import -- /本機下載路徑/content.json
npm test
npm run build
npm run test:e2e
```

3. 檢查 `public/data/content.json` 的 Git 差異及自由文字授權。匯入工具拒絕未知欄位，但不會判斷文字中是否包含個資。不要將內部 CSV、Sheets 備份或測試資料匯入公開目錄。
4. 提交原始碼與核准的公開 JSON，使用現有 GitHub／Netlify 整合建立 Deploy Preview。此專案未新增自動推送或自動部署憑證。
5. Netlify 建置指令 `npm run build`、發布目錄 `dist`、Node 24；`netlify.toml` 固定正式 published 模式。Netlify／Vercel 僅在更換後台網址時需要覆寫 `VITE_ADMIN_URL`；環境變數更改後重新建置。禁止以 `VITE_CONTENT_MODE=demo` 當正式環境設定。Vercel 沿用既有設定並指定 published；需部署完整 2A 前台程式，重新部署舊提交不會新增 `/admin`。
6. 預覽首頁公告、合作機構列表／詳細頁、課程分類／詳細頁、Google Forms 連結、手機選單、既有成果庫與資源。核准後依既有流程正式部署。首次 JSON 為空時，正式課程及合作機構會顯示尚待公告，示範課程仍可在展示模式查看。

## 7. 個人 Gmail 無法滿足條件時

保持 WRITE_ENABLED=false，必要時封存不適合的網頁部署。免費替代方式是：由受信任維護者直接在受限 Google Sheets 維護公開文案，於本人帳號的 Apps Script 編輯器執行私人 previewInEditor_（輸出至受限執行紀錄，僅公開欄位，沒有網頁端點或內容寫入），或使用原有網站檔案維護，人工去識別與審核 JSON，再交付 GitHub／Netlify。這個方式不提供多管理員網頁 CRUD，也不假稱原驗收已達成；保留版本紀錄與人工覆核，沒有匿名寫入端點。

另一選項是由合資格非營利組織評估 Google Workspace for Nonprofits（資格及方案由 Google 決定，不能保證取得），再以可管理的帳號環境重新測試；仍維持使用者執行及白名單。不要改成以擁有者執行的公開代理 API，也不要接收使用者傳入 email 當授權依據。

## 8. 維護與參考

每次更新 Apps Script 程式、OAuth、部署執行者、存取選項或帳號環境前，先停止寫入並清除舊驗收紀錄；建立新版本部署後重做身份測試。變更試算表欄位須有明確遷移程式，不能直接更動表頭。API 配額、授權使用者速率及 Drive／Sheets 容量依免費 Google 帳號當時規範，適用小型內部管理，未承諾無上限。

Google 官方說明：[Web apps](https://developers.google.com/apps-script/guides/web)、[Session](https://developers.google.com/apps-script/reference/base/session)、[Webapp manifest](https://developers.google.com/apps-script/manifest/web-app-api-executable)、[Advanced Drive](https://developers.google.com/apps-script/advanced/drive)、[Drive file capabilities](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)、[OAuth verification](https://developers.google.com/apps-script/guides/client-verification)。實際 Google UI 與政策以部署時官方資訊為準。
