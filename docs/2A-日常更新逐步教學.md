# 後台編輯到前台公開：日常更新逐步教學

適用於目前已完成設定、可由試算表擁有者本人編輯的 CCSA 管理後台。以下以更新一則公告為例，機構、課程及招募設定也使用相同發布流程。

日常更新只處理後台內容、公開資料檔及 GitHub 發布。已設定好的 Apps Script 程式、指令碼屬性及試算表保留原狀；重新執行初始化會再次關閉寫入，不是日常更新步驟。

## 先認識三個入口

| 入口 | 連結 | 用途 |
| --- | --- | --- |
| 管理後台入口 | [前往管理入口](https://ccsa-ai-empowerment.vercel.app/admin) | 使用已授權的 Google 帳號編輯內容 |
| GitHub 公開資料夾 | [開啟 main 的 public/data](https://github.com/milkpufftw-arch/ccsa-ai-empowerment/tree/main/public/data) | 上傳最新公開資料檔、建立更新申請 |
| 正式前台 | [開啟民眾觀看的網站](https://ccsa-ai-empowerment.vercel.app/) | 部署後確認對外顯示的結果 |

Google、GitHub、Vercel 是不同服務，登入狀態各自獨立。GitHub 右上角若顯示 **Sign in**，須先登入能編輯本專案的 GitHub 帳號，才會有上傳功能。預覽網站若要求登入 Vercel，使用管理這個 Vercel 專案的帳號登入。

## 「儲存」「已發布」「正式上線」有何不同

| 做到哪裡 | 資料狀態 | 民眾是否已看到這次變更 |
| --- | --- | --- |
| 後台儲存草稿 | 已存進內部試算表 | 尚未 |
| 後台設為已發布並儲存 | 可納入下一次公開匯出 | 尚未 |
| 下載及上傳 content.json，建立 PR | 已提出網站更新，可建立預覽 | 正式網站尚未更新 |
| 預覽檢查完成，合併 PR，正式部署 Ready | 公開網站已部署這次更新 | 此時到正式網站確認 |

本版是人工確認後發布，不會在後台一按儲存就立即同步前台，也沒有依公告日期自動排程上線的功能。

## 第 1 步：在後台新增或編輯公告

1. 開啟 [管理入口](https://ccsa-ai-empowerment.vercel.app/admin)，按「使用Google帳號前往管理後台」。
2. 確認後台右上角是本人帳號，左側選「公告」。
3. 新公告按「＋ 新增公告」；修改舊公告時，找到原來那筆並按「編輯」，以保留原ID。
4. 填寫以下欄位：

| 欄位 | 填寫方式 |
| --- | --- |
| 標題 | 民眾會看到的公告名稱 |
| 分類 | 例如「最新消息」或「課程通知」 |
| 摘要 | 用簡短文字說明公告重點 |
| 內容（純文字） | 完整且已確認可公開的內容 |
| 公告日期 | 填實際公告日期；首頁依此日期由新到舊排序 |
| 發布狀態 | 撰寫中選「草稿」；確認可公開後選「已發布」 |

5. 可先存成草稿，再按「預覽」或表單中的「預覽公開欄位」核對。
6. 確認可以公開後，將發布狀態改為「已發布」，按「儲存」。
7. 看到儲存成功訊息，回清單確認狀態標籤是「已發布」。

**完成檢查：** 後台清單有這筆資料，狀態為已發布。此時正式前台仍可能顯示舊內容，屬於正常流程。

## 第 2 步：預覽並下載最新 content.json

1. 左側選「公開資料發布」。
2. 按「預覽已發布JSON」。
3. 在預覽內容搜尋剛才的公告標題。只有已發布資料會出現，草稿及下架資料不會匯出。
4. 確認公開文字正確後，關閉預覽，按「下載公開JSON」。
5. 在瀏覽器按 **Ctrl+J** 找到最新下載的檔案，必要時按「在資料夾中顯示」。
6. 確認完整檔名是 **content.json**。若下載成 `content (1).json`，把最新檔案改回 `content.json`；Windows 若隱藏 `.json` 副檔名，檔名部分改成 `content` 即可，避免變成 `content.json.json`。

這一份檔案是目前**所有已發布內容的整份公開快照**，不只是這一則公告。每次更新都重新下載最新整份，之後完整取代網站的舊檔，不用自行編輯或拼接 JSON。

**完成檢查：** 最新檔案名稱正確，預覽中找得到公告標題。只交付後台匯出的公開 `content.json`，不交付內部試算表、管理員表、操作紀錄或備份；公開文字本身仍須人工確認。

## 第 3 步：登入 GitHub，開啟正確上傳位置

1. 開啟 [main 分支的公開資料夾](https://github.com/milkpufftw-arch/ccsa-ai-empowerment/tree/main/public/data)。
2. 若右上角顯示「Sign in」，先登入能編輯本專案的 GitHub 帳號。
3. 確認資料夾路徑是 **public / data**，起始分支為 **main**。
4. 按「Add file → Upload files」。也可以登入後直接開啟 [公開資料上傳頁](https://github.com/milkpufftw-arch/ccsa-ai-empowerment/upload/main/public/data)。
5. 拖入剛下載的最新 `content.json`。它應取代 `public/data/content.json`。

前次使用的 `codex/owner-only-admin-writes` 是特定功能更新分支；完成合併後，日常更新從最新 `main` 開始，避免以舊資料或舊程式當起點。

**完成檢查：** 這次變更的檔案是 `public/data/content.json`。如果看到根目錄的 `content.json`、`content (1).json` 或 `content.json.json`，先修正上傳位置或檔名，再提交。

## 第 4 步：提交到新的內容更新分支

1. 上傳後找到提交區；若畫面只有「Commit changes」按鈕，先按它開啟提交設定。
2. 提交標題可填「更新公開資料：新增課程通知」，或清楚寫出這次更新的內容。
3. 選擇 **Create a new branch for this commit and start a pull request**，讓這次資料先進入獨立更新分支。
4. 可使用系統產生的分支名稱；若自行命名，建議用日期及序號，例如 `content-update-20261123-01`，每次使用不同名稱。
5. 依畫面按「Propose changes」或「Commit changes」完成提交。

分支可理解為這次更新的「待確認版本」；main 則是正式部署所使用的版本。使用新分支才能先看預覽再決定上線。

**完成檢查：** 頁面進入新分支或「Open a pull request」比較頁，尚未改變正式網站。

## 第 5 步：建立更新申請（Pull request，簡稱 PR）

1. 在「Open a pull request」畫面確認 **base: main**，**compare: 這次建立的新分支**。
2. 顯示「Able to merge」表示目前沒有合併衝突。
3. 「Add a title」填這次更新名稱，例如「更新網站公告：課程通知」。
4. 說明欄若要填寫，點 **Write**，簡短描述改了哪些公開內容。說明可留白，不影響建立。
5. 按大說明框右下方綠色的 **Create pull request**。

「Nothing to preview」出現在空白說明欄的 **Preview** 分頁時，只表示沒有說明文字可預覽，不代表網站沒有部署。真正建立 PR 要按綠色 Create pull request。

**完成檢查：** 網址變成 `/pull/數字`，頁面有 PR 編號及 Open 狀態。

## 第 6 步：從 Vercel 留言開啟這一次的網站預覽

1. 在剛建立的 PR 頁面找到 **vercel Bot** 留言，左側是黑底白色三角形圖示。
2. 等表格的 Deployment 狀態變成 **Ready**。
3. 點該表格 Actions 欄位的 **Preview 連結**，開啟這次分支的預覽網站。
4. 預覽若要求登入 Vercel，使用管理此專案的帳號登入後繼續。

每次 PR 的預覽網址可能不同，請每次都從該次 PR 的 Vercel 留言開啟。PR 的說明／留言框也有一個名為 Preview 的分頁，那只預覽文字，不會開啟網站。

**完成檢查：** 新分頁顯示網站，而不是 GitHub 留言框或 Vercel 的舊 Production 部署詳情頁。此時測試的是預覽版本，正式網址尚未更新。

## 第 7 步：在預覽網站確認內容

1. 點左上「共創未來」回首頁，或使用目前預覽網址的根目錄 `/`。`/about` 是「認識計畫」頁，不會列出首頁公告。
2. 按 **Ctrl+F** 搜尋 **計畫新鮮事**，或往首頁下方滑動。
3. 在公告區找到這次的標題，核對分類及公告日期。
4. 點公告標題，確認詳細頁的摘要與全文正確。
5. 若這次修改的是舊公告，確認看到的是新內容；若下架公告，確認公開清單已移除該筆。

「計畫新鮮事」是首頁的公告區塊，不是導覽列按鈕。首頁最多列出五則公告，依公告日期由新到舊排序；較舊資料可能不在首頁前五則。

**完成檢查：** 想公開的內容在預覽網站正確顯示，且確定可以讓民眾看到。若顯示「公告暫時無法載入」，代表資料讀取失敗，先保留 PR 並回報錯誤，不要用空公告狀態判定資料已下架。

## 第 8 步：合併更新，觸發正式部署

1. 回到 GitHub 的這次 PR。
2. 查看檢查結果。等待 Vercel 等檢查完成且成功，並確認沒有合併衝突。
3. 在頁面下方按綠色 **Merge pull request**。
4. 再按 **Confirm merge**。
5. 確認 PR 顯示 **Merged**。

不要按「Close pull request」來發布；那會關閉申請，不會將更新合併到 main。合併也不等於網站瞬間完成更新，Vercel 還需要建置及部署。

**完成檢查：** PR 已合併，main 已包含這次的公開資料更新。

## 第 9 步：驗收正式前台

1. 在 Vercel 專案的 **Deployments** 找到這次合併後新產生的 **Production** 部署。
2. 確認來源是 **main**、建立時間對應這次更新、狀態為 **Ready**。預覽版的 Ready 與正式版的 Ready 是不同部署。
3. 開啟固定的 [正式網站](https://ccsa-ai-empowerment.vercel.app/)，按 **Ctrl+Shift+R** 強制重新整理。
4. 到首頁「計畫新鮮事」查看公告，點開核對全文。測試正式網站時使用這個固定網址，不使用前面分支預覽的網址。

**完成檢查：** 正式網站已出現這次正確內容，這一輪更新才算完成。

## 其他資料的前台位置

| 後台項目 | 前台位置 | 額外要確認的設定 |
| --- | --- | --- |
| 合作機構 | AI種子機構 `/seed` 的合作機構清單及詳細頁 | 發布狀態為已發布，Logo 使用已核准公開的網址 |
| 課程活動 | 培力課程與活動 `/courses` 及詳細頁 | 發布狀態、報名狀態分開設定；開放報名需有效 Google Forms 網址 |
| 公告 | 首頁「計畫新鮮事」及公告詳細頁 | 發布狀態為已發布，首頁依公告日期排序 |
| 招募設定 | AI種子機構 `/seed` 的申請說明與按鈕 | 已發布、招募狀態開放中，且現在落在招募起訖日期內（臺灣日期） |

所有項目都使用同一份最新 `content.json`。下架、刪除及修改報名狀態後，也須重新下載、上傳、預覽、合併及部署，才能改變正式網站。

## 遇到問題時先看這張表

| 現象 | 先確認 |
| --- | --- |
| 看不到 Add file／Upload files | GitHub 是否已登入可編輯專案的帳號；可用本手冊的直接上傳頁 |
| Nothing to preview | 是否點到 PR 說明或留言框的文字預覽；網站預覽請找 vercel Bot 表格的 Preview |
| 只有首頁，找不到公告按鈕 | 公告在首頁靠下方的「計畫新鮮事」區塊，點的是公告標題 |
| 找不到計畫新鮮事 | 是否開到 `/about`；點「共創未來」回首頁，Ctrl+F 搜尋正確文字 |
| 後台有公告，匯出檔卻沒有 | 公告是否設為已發布且儲存；是否重新下載最新檔案 |
| 上傳後預覽仍是舊內容 | 檔案是否為 `public/data/content.json`、是否傳到此次 compare 分支、是否等最新部署 Ready |
| 公告暫時無法載入 | 資料讀取失敗，與空清單不同；登入受保護的預覽並重新整理，持續發生時回報畫面 |
| 最新公告將陸續更新 | 公開公告清單為空；確認匯出檔 announcements 有資料及部署版本正確 |
| 預覽有公告，正式站沒有 | PR 是否已合併；新的 Production 是否已 Ready；是否開對正式網址 |
| 下架後正式網站仍有資料 | 是否重新匯出、替換公開檔案並完成正式部署 |

## 每次完成前的六項核對

- [ ] 後台內容已儲存，發布狀態正確。
- [ ] 已下載最新的公開 `content.json`，文字內容確認可以公開。
- [ ] GitHub 更新的是 `public/data/content.json`，並建立新的內容更新 PR。
- [ ] 這次 PR 的 Vercel 預覽顯示正確內容。
- [ ] PR 已合併，新 Production 已 Ready。
- [ ] 固定正式網址顯示正確內容。
