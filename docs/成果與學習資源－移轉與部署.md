# AI 應用成果庫與學習資源管理

## 資料與權限

三個新增工作表都在現有後台的同一份私人試算表內。Google 登入、白名單、試算表編輯權限、停寫開關、版本衝突檢查及操作紀錄沿用既有後台。

| 工作表 | 用途 |
| --- | --- |
| `Showcases` | AI 應用成果、展示圖片、工具、步驟及公開連結 |
| `LearningResources` | AI 學習資源、資源類型、適用對象及教材連結 |
| `LibraryCategories` | 兩個模組的分類、分類狀態及順序 |

分類以 ID 關聯。可以改名或排序，已有資料使用的分類須先解除關聯才能下架、刪除或改變適用模組。既有成果保留原本網址中的 ID，新增與複製資料由伺服器產生 ID。複製後預設為草稿；只有草稿或已下架的資料可刪除。發布日期是顯示用欄位，公開與下架由發布狀態控制。

Apps Script 擁有者的定時觸發條件每分鐘檢查是否有內容變更。有變更時從私人試算表產生一份獨立的 Drive JSON 檔案，無變更時約每四分鐘更新快照時間。檔案只含三張表的已發布白名單欄位。專用 Google 服務帳戶僅具此快照的讀取權限。Vercel 的 `GET /api/library` 在伺服器端取得檔案並驗證欄位及產生時間，再回傳給網站。開啟中的頁面每分鐘更新一次，回到分頁時也會重新讀取。正常情況約需一至兩分鐘，實際時間取決於 Google 觸發條件排程。API 遇到上游錯誤、格式錯誤或超過十分鐘的快照時會回傳 503。

Vercel 沒有設定這項整合時，前台保留原本打包的成果和資源供檢視。啟用同步後，前台以快照為準。合作機構、課程活動、公告及招募維持原來的 `content.json` 匯出與部署流程。

## 先在 Vercel Preview 驗證

1. 建立獨立的測試試算表與 Apps Script 專案。可使用全新試算表，或經去識別化且獲准用於測試的副本。備份時請保留所有原資料表、欄位及保護設定，並記錄來源與備份檔案位置。
2. 在測試 Apps Script 專案匯入本分支 `apps-script/` 的所有 `.gs` 檔、`Index.html` 及 `appsscript.json`。啟用 Drive API v3 進階服務，並確認關聯的 Google Cloud 專案已啟用 Google Drive API。
3. 在 Apps Script 指令碼屬性設定 `SPREADSHEET_ID` 為測試試算表 ID。新建空白試算表先由擁有者執行 `initialize_` 建立原六張表。準備好測試試算表的備份後，設定 `LIBRARY_BACKUP_CONFIRMED` 為這份測試試算表的 ID。由擁有者執行 `migrateLibrary_`。確認新增三張表，含 6 筆成果、5 筆資源及 17 筆分類。
4. 在 Google Cloud 建立專供這個 Preview 使用的服務帳戶並啟用 Google Drive API。服務帳戶不需要 Google Cloud IAM 專案角色或試算表權限。由有權限的管理者產生專用 JSON 金鑰，將其 `client_email` 填入 Apps Script 指令碼屬性 `LIBRARY_SNAPSHOT_READER`。金鑰留在安全的部署設定流程。
5. 由試算表擁有者執行 `installLibraryPublisher_`，完成新增 Google OAuth 範圍的授權。確認執行紀錄印出 `LIBRARY_PUBLIC_FILE_ID`，且 Apps Script 觸發條件頁面只有一個 `refreshLibrary_`。在 Drive 檢查快照的分享只包括擁有者及專用服務帳戶。若 Google Workspace 禁止與該服務帳戶共享，請由網域管理員核可這項私人分享後再驗收。
6. 部署測試 Apps Script 網頁應用程式，執行身分為「存取網頁應用程式的使用者」，存取者為「具有 Google 帳戶的任何人」。用實際帳號依 [原後台安全驗收](2A-部署與安全驗收.md) 驗證登入、白名單及試算表權限，再依既有 `owner_only` 或多人驗收流程啟用測試環境的寫入。Apps Script 新版本及新增授權範圍可能要求已授權管理者重新同意。
7. 在 Vercel 為此開發分支設定 **Preview** 環境變數，再部署該分支。正式環境請使用獨立快照及服務帳戶。以下表格前三項供 Vercel Function 使用，請在 Vercel 伺服器環境設定，尤其是私鑰。

| Vercel Preview 變數 | 值 |
| --- | --- |
| `LIBRARY_PUBLIC_FILE_ID` | Apps Script 執行紀錄中的快照 ID |
| `LIBRARY_DRIVE_CLIENT_EMAIL` | 服務帳戶 JSON 的 `client_email` |
| `LIBRARY_DRIVE_PRIVATE_KEY` | 服務帳戶 JSON 的 `private_key`，包含 PEM 標頭與結尾，可使用原始換行 |
| `VITE_ADMIN_URL` | 測試 Apps Script 部署的 `/exec` 網址，此公開 URL 會進入前端 |

8. 在 Preview 開啟 `/api/library`，確認回傳 HTTP 200 及 `categories`、`showcases` 和 `resources`。從 `/admin` 進入測試後台，逐項確認新增草稿、發布、改名、替換圖片與下架。實際用未授權或只有檢視權限的 Google 帳戶驗證拒絕寫入。使用 Vercel 專案 Deployments 頁面顯示的 Preview URL 分享驗收。

## 正式環境切換與復原

取得正式上線同意後，由擁有者先完整備份正式工作簿，再用正式設定重複上述步驟。既有正式後台已有六張表時，直接執行 `migrateLibrary_`。遷移程式只補上新表及缺少的種子 ID，完成後會寫入 `LIBRARY_SCHEMA`，再次執行也不會覆蓋已編輯的內容或重建已刪除內容。發現現有表頭不符時應停止並比對備份。請保留原正式 Apps Script 部署版本及 Vercel 部署以便復原。

若需復原，先在 Apps Script 設 `WRITE_ENABLED=false`，並停用 `refreshLibrary_` 觸發條件。必要時收回服務帳戶讀取權限、輪替金鑰，將 Apps Script 和 Vercel 切回上一個部署版本。保留已新增的工作表與操作紀錄供檢查；由擁有者逐筆核對備份後再處理資料。啟用或撤回 Vercel 環境變數需要一次部署，日常內容異動由觸發條件處理。

## 日常操作

使用「AI 應用成果庫管理」、「AI 學習資源管理」或「成果與資源分類管理」。長文可換行並用「加粗選取文字」標記重點。上傳 JPG、PNG 或 WebP（單張原始檔最多 12 MB）時，瀏覽器會縮圖並轉成 JPEG，封面也可改用 HTTPS 圖片網址。展示圖最多 8 張，包含相同欄位內的圖片容量上限；大圖可改用 HTTPS 網址。附件及教材欄位每行以 `名稱｜HTTPS 網址` 填寫。外部圖片、影片及檔案須由內容管理者確認公開權限及授權。

Apps Script 內的快照上限是 3.5 MB；內容量接近上限時可把已上傳圖改成核准的 HTTPS 圖片網址。在後台查看最近產生快照的時間，並在 Apps Script「執行項目」檢查觸發條件。如果儲存成功而前台未更新，先查驗快照時間及 `/api/library` HTTP 狀態。這可以區分 Apps Script 同步失敗與 Vercel 未取得快照。

維護者可執行 `node scripts/generate-library-seed.mjs --check` 驗證移轉種子與既有前台資料完全同步。
