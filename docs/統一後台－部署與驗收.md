# 統一 CCSA 管理後台與前台同步

新版 Apps Script 管理六個模組。合作機構、課程、公告及招募使用新的 `GET /api/content`；成果庫與學習資源繼續使用 `GET /api/library`。兩個端點各自驗證私人 Drive 快照，網頁開啟時及每分鐘讀取。草稿、下架資料、管理帳號、稽核和內部備註均不公開。

## 更新現有新版後台

1. 核對原有及新版 Apps Script 的 `SPREADSHEET_ID` 指向同一份工作簿。備份現行 Apps Script 版本與試算表，以便比對及回復。
2. 在現有新版 Apps Script 更新與本分支相同的 `.gs` 和 `Index.html`。使用之前的單檔安裝套件時，使用新版合併檔 `Code.gs` 與 `Index.html`。保留既有指令碼屬性和資訊清單。更新既有專案時保留原資料表和目前的寫入權限。
3. 暫時新增 `UnifiedSetup.gs`，在其中定義 `function runContentPublisher() { installContentPublisher_(); }`。由工作簿擁有者儲存並從編輯器執行。拿到執行紀錄中的 `CONTENT_PUBLIC_FILE_ID` 後，刪除暫用檔並儲存。
4. 在「管理部署作業」編輯現有新版部署並選擇新版本，保留已驗收的 `/exec` 網址。確認六個模組、既有公告、課程關聯和招募狀態都正確。

## Preview 驗收及正式切換

1. 用本機 Sheets 測試替身驗收新增、發布和下架。在 Vercel Preview 檢查頁面與連結。若本分支也要線上驗收真實資料，可設定 `CONTENT_PUBLIC_FILE_ID`、`VITE_ADMIN_URL` 和既有的三項 `LIBRARY_*` 設定。`VITE_ADMIN_URL` 填新版 Apps Script 的 `/exec`。兩個快照共用現有的 Google 服務帳戶和私鑰，私鑰留在安全環境變數欄位。
2. 在 Preview 檢查 `/api/content` 的既有公告、課程、機構與招募，確認原有公開連結和報名連結正確。檢查 `/api/library` 和既有成果明細。已設定快照的環境遇到資料錯誤會顯示載入錯誤。尚未設定新快照的環境會沿用原有公開 JSON。
3. 統一入口前確認工作簿中的發布狀態符合正式站應顯示的內容。正式環境設定 `CONTENT_PUBLIC_FILE_ID`，沿用既有的三項 `LIBRARY_*` 設定。正式 `/admin` 預設指向已驗收的新版 Apps Script；若環境已有 `VITE_ADMIN_URL`，檢查覆寫值也指向同一新版。從已審核提交建立 Production 候選部署、核對兩條 API，再切換正式網域。
4. 日常作業在同一個後台發布或下架，通常一至兩分鐘即可在前台看到結果。原有「公開資料發布」仍提供預覽及備份下載。

## 回復

若前台部署異常，先將正式網域切回先前已驗收的部署，保留兩份 Sheets 快照與資料。若新版 Apps Script 介面發生問題，在其部署管理中切回上一個 Apps Script 版本。四類快照故障時可在 Vercel 移除該環境的 `CONTENT_PUBLIC_FILE_ID` 並重新部署，恢復使用隨網站附帶的公開 JSON；此回復方式可能顯示先前匯出的資料，切換前請核對。
