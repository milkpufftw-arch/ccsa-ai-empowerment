# 2A 社工操作與日常維護

## 第一次使用

由計畫管理員提供管理網址。使用自己的 Google 帳號登入，依 Google 畫面授權；不需要另外註冊密碼。首頁右上角應顯示您本人帳號。如果是另一個帳號，切換 Chrome 個人檔案後重新開啟。

若看到「無法存取」，請請計畫管理員確認您已列入白名單，並有內部試算表的編輯權限。若看到「唯讀模式」，可能是維護人員尚未啟用寫入、已暫停寫入，或目前採擁有者專用模式而您不是試算表擁有者。請勿另行開放試算表分享。只有一位管理員時，可依 [擁有者啟用與發布練習](./2A-擁有者啟用與發布練習.md) 設定並練習第一則公告。

## 機構、課程、公告

1. 左側選擇「合作機構」、「課程活動」或「公告」。手機版導覽位於上方。
2. 按「新增」，填寫有 ＊ 的必填欄位。日期使用日期選擇器；課程內容一行一項，公告內容使用純文字。
3. 先存成草稿。用列表「編輯」回到同一筆資料，不要為了修改再新增一筆。
4. 「預覽公開欄位」可查看文章內容，不含內部備註。確認機構公開授權、日期、網址與文案，不填入兒少資料或私人聯絡方式。Logo 須先由維護人員放入網站核准檔案，再貼入 HTTPS PNG/JPG/WebP 網址，此階段沒有檔案上傳功能。
5. 機構及課程可先改為「待審核」，同仁確認後再改「已發布」。多人驗收模式的管理員具相同內容管理能力；擁有者專用模式則只有試算表擁有者能編輯。待審核是工作流程標記，沒有另設審核角色。
6. 按「儲存」並確認成功訊息。若顯示驗證錯誤，依提示修改。若顯示其他同仁已修改，先關閉表單、重新進入列表再開啟，不要直接覆蓋。

列表提供關鍵字搜尋及發布狀態篩選。下架前會確認；刪除僅允許草稿或已下架資料，且無法復原。已有關聯課程的機構，須先解除關聯或處理課程後才可刪除；已有公開課程時亦不能直接下架機構。

**「儲存成功」表示內部資料已更新，不表示網站已更新。** 下架、刪除及更改報名狀態，都要再次匯出並部署才會反映在公開網站。已公開的 JSON 或舊版 Git 紀錄不能靠下架自動消失；如果誤放個資，立刻聯絡維護人員處理移除、重新部署及版本／快取清理。

## 招募設定

「招募設定」只有一筆，請選「編輯」。既有正式 Google Forms 網址已預填，不必重建申請表。

填寫開始及截止日期、招募狀態、招募說明，必要時加入錄取公告網址。開始日期不得晚於截止日期。「招募狀態」與「發布狀態」是兩個欄位：必須設定為已發布才可匯出；設定為開放中且今天在起訖日期內，公開網站才顯示申請按鈕。招募日期以臺灣日期計算，截止日全天有效。

網站的按鈕不會自動關閉 Google Forms 接收回覆。截止時請另外由表單擁有者關閉回覆，或調整表單提示；若要即時控制外部表單本身，必須在 Google Forms 裡操作。

## 更新公開網站

1. 選「公開資料發布」→「預覽已發布 JSON」。只會包含已發布的機構、課程、公告及招募設定，沒有管理員帳號、操作紀錄、內部備註。
2. 人工確認文字可公開；自由文字即使通過欄位檢查也可能含個資，必須審閱。
3. 按「下載公開 JSON」。下載到您自己的裝置，再放入計畫受限的 Google Drive「公開資料交接」資料夾。不要上傳整份內部試算表或 AuditLogs。
4. 交由負責網站的維護人員匯入及審核，或依 [不用終端機的 GitHub 更新步驟](./2A-擁有者啟用與發布練習.md#第五步透過-github-更新前台不用終端機) 上傳至 `public/data/content.json` 並建立 PR。溝通方式依既有團隊流程，本系統不會自動寄信或發布通知。
5. 在預覽網站確認電腦／手機版、機構介紹、課程詳細頁、公告與 Google Forms 連結後，再由維護人員依既有流程部署。

網站維護人員的具體指令及安全設定見 [部署與安全驗收](./2A-部署與安全驗收.md)。

## 首頁數字如何看

「合作機構」為實際建檔總數，另外列出已發布數量；「已發布課程」只計已發布記錄。預期目標由維護者設定，未設定時顯示尚未設定，不會拿目標當實際成果。課程數量不是參與人次，也不表示課程已辦理完畢。最新公告與最近修改紀錄都是內部管理資訊，可包含草稿及待確認操作。

## 常見訊息

| 訊息 | 處理方式 |
| --- | --- |
| 無法辨識Google身分 | 停止操作，請維護人員核對 Google 授權及以存取者執行設定，不要提供 email 給前端繞過 |
| 未列入白名單／沒有編輯權限 | 請擁有者確認 AdminUsers 與 Sheets 分享兩項都已完成 |
| 資料已變更 | 重新載入後再編輯，請與同時操作的同仁確認 |
| 其他同仁正在儲存 | 稍後再操作；不要連按新增 |
| 儲存狀態待確認、連線失敗或操作未完成 | 先重新進入列表比對是否已建立／修改，再聯絡維護者；不要立即重做新增 |
| 工作表欄位或公式錯誤 | 停止直接編輯試算表，請維護者從版本紀錄檢查表頭、ID、日期及公式 |
| 網站資料暫時無法載入 | 維護人員確認 content.json 是否存在、格式是否正確；不代表要開放內部 Sheets 分享 |

## 維護人員固定工作

若編輯器沒有列出 `_` 結尾的私人維護函式，請依 [部署文件的暫時改名步驟](./2A-部署與安全驗收.md#編輯器未列出私人函式) 操作。執行完立即恢復原名並儲存，恢復前不要建立或更新網頁部署。

- 管理員異動：加入時由擁有者執行 `addAdmin_`，並另分享試算表編輯權限；移除時由擁有者在指令碼屬性暫填 REMOVE_ADMIN_EMAIL，再執行 deactivateAdmin_；程式保留原ID並更新狀態、時間、版本及操作紀錄，完成後清除暫存屬性。另撤銷 Sheets 分享及 Apps Script 專案編輯權（若原本有）。將帳號異動原因留在私人維護紀錄，勿提交帳號清單到 GitHub。
- 每次更新後：確認 AuditLogs 有 applied 紀錄；failed 表示有失敗，仍應核對實際資料；pending 表示結果不確定。依 recordId、事件及時間比對資料與版本紀錄，確認是否部分寫入，處理完成後由維護者在私人紀錄註明，不要刪除原事件。
- 定期備份：依組織保存政策，將內部 Sheet 複本放在受限 Drive 備份資料夾；將已公開且核准的 JSON 保留在 Git 版本紀錄。定期檢查資料夾分享、儲存容量及還原能力，備份不放公開 Repository。
- 還原：先設 WRITE_ENABLED=false，保存事故現況，再從 Sheets 版本紀錄／受限備份還原並核對 ID、version、關聯與最近操作。公開資料則以核准的 Git 版本重新建置、預覽及部署。還原後重新做安全驗收再開啟寫入。
- 暫停寫入：Apps Script 私人編輯器執行 `disableWrites_`，或在指令碼屬性設 WRITE_ENABLED=false。清除 SECURITY_REVIEW_JSON 可使多人模式的舊驗收失效，但不會停用擁有者模式；所有模式都應以 WRITE_ENABLED=false 停寫。不要把網址改成匿名執行。
- 版本更新：本 Repository 是程式來源；變更前停寫、備份並確認差異，將 `.gs/.html/appsscript.json` 更新至 Apps Script，再以新版本更新現有部署；實際設定與授權驗收後才恢復。更換試算表或 Google 專案不得沿用未驗證的舊安全紀錄。

## 尚待正式驗收的部分

本機自動測試可驗證應用程式的判斷、資料契約及瀏覽器操作；無法證明您的個人 Gmail 部署可正確辨識帳號、Google 配額允許足夠管理員、或真實 Sheets／Netlify 已成功部署。正式驗收須按部署文件逐項完成。若 Gmail 無法符合安全要求，保持網頁寫入停用，採受限試算表＋人工審閱公開 JSON 的免費替代流程。
